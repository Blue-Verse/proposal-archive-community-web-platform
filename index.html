프로젝트 소개

노코드 프로토타입의 시각적 구조와 기획 로직을 그대로 계승하면서, 성능·보안·확장성을 갖춘 커스텀 웹 플랫폼으로 전환합니다. CMS·커뮤니티·회원 시스템·어드민을 통합 구축하고, SEO 최적화와 ADMS·매칭 시스템 모듈 확장이 가능한 아키텍처로 설계합니다.

핵심 요구사항 분석

  • 정보 아카이브 CMS — 카테고리별 상세 페이지, 정책·가이드라인 게시판 구조, 관리자가 직접 생성·수정·삭제 가능한 콘텐츠 관리 시스템
  • 커뮤니티 기능 — 권한 그룹별 게시판 분리, 댓글·좋아요·북마크 등 네이버 카페 수준의 기본 소셜 인터랙션
  • 회원 시스템 — 이메일·비밀번호 로그인 + 카카오/네이버/구글 SSO, 개인별 활동 로그 및 관심 게시물 저장
  • 관리자 페이지 — 회원·게시물·권한 통합 관리, DB 현황 대시보드
  • SEO 최적화 — Next.js SSR/SSG 기반 시멘틱 마크업, 동적 OG/메타 태그, sitemap.xml·robots.txt 자동 생성, JSON-LD 구조화 데이터
  • 확장성 설계 — ADMS(광고 관리)·전문가 매칭 시스템을 모듈로 즉시 추가할 수 있는 도메인 분리 아키텍처
  • 보안 — HTTPS, 비밀번호 bcrypt 해싱, JWT + Refresh Token, OWASP Top 10 대응, 민감 데이터 컬럼 암호화

제안 포인트

1. 노코드→커스텀 전환에 특화된 접근

기존 프로토타입의 시각적 구조와 기획 로직을 그대로 보존하면서, 성능·확장성 한계를 해소하는 마이그레이션 전략으로 진행합니다. 첫 주에 노코드 프로토타입을 분석하여 화면 흐름·데이터 모델·비즈니스 로직을 도출하고, 이를 PRD 및 ERD로 정형화한 뒤 개발에 착수합니다.

2. SEO 최우선 기술 스택

Next.js App Router의 SSR/SSG·ISR을 활용하여 정책 키워드 검색 시 구글·네이버 최상단 노출을 위한 정적 HTML을 사전 렌더링합니다. 카테고리·게시물 메타 태그를 콘텐츠 기반으로 자동 생성하고, JSON-LD 구조화 데이터(Article, BreadcrumbList, Organization)를 적용합니다.

3. 확장 모듈 대응 아키텍처

NestJS 모듈 기반 도메인 분리(Account · Archive · Community · Admin · Notification · Search) 구조를 채택합니다. 차후 ADMS·매칭 모듈은 신규 모듈 추가만으로 통합되며, 기존 코드 수정 없이 점진적 확장이 가능합니다. 데이터베이스는 카테고리·태그·관계 테이블을 일반화하여 콘텐츠 유형 추가에 유연하게 대응합니다.

4. 권한 모델링 전문성

전자결재 SaaS(7 사용자 역할, 6계층 보안), VC 펀드 포탈(다단계 권한·DLP·GeoIP) 등 RBAC 모델링 경험을 보유하고 있습니다. 본 프로젝트의 "사용자 권한별 게시판" 요구사항을 CASL 또는 RBAC 미들웨어로 선언적으로 구현합니다.

5. 1순위 "산출물 완성도" 충족

유사 프로젝트 수행 경험을 바탕으로 검증된 패턴(인증, RBAC, CMS, 검색)을 재사용하여 안정성을 확보합니다. 마일스톤 단위 검수를 통해 단계별 완성도를 보장하며, 프로젝트 종료 시 소스 코드·API 문서·운영 매뉴얼·SEO 보고서까지 정식 산출물로 납품합니다.

PRD (Product Requirements Document)

프로젝트 요구사항을 정의하고 기능 범위를 명확히 합니다.

1. 프로젝트 배경 및 목적

현재 노코드 툴 기반 프로토타입은 시각적 구조와 기획 로직 검증은 완료했으나, 성능·보안·확장성 측면에서 운영 단계로의 전환에 한계가 있습니다. 본 프로젝트는 산재된 정책·가이드라인을 구조화하여 제공하는 정보 아카이브와, 사용자 권한별로 활동 가능한 커뮤니티 기능을 중심으로 한 커스텀 웹 플랫폼을 구축하는 것을 목표로 합니다.

강력한 CMS로 관리 효율을 극대화하고, SEO 최적화로 정책 키워드 검색 시 상위 노출을 확보하며, 향후 광고 관리 시스템(ADMS) 및 전문가/사용자 매칭 시스템을 모듈로 확장 가능한 아키텍처를 통해 지속적인 비즈니스 성장 기반을 마련합니다.

3. 기능 요구사항

3.1 정보 아카이브 (CMS)

  • [필수] 카테고리 트리 구조 (대분류/중분류/소분류 3계층)
  • [필수] 카테고리별 상세 페이지 (사진+정보 나열형 게시판 구조)
  • [필수] 정책·가이드라인 콘텐츠 CRUD (Lexical 리치 에디터)
  • [필수] 이미지·첨부파일 업로드 (S3 + CloudFront)
  • [필수] 카테고리·콘텐츠 노출 순서 드래그 정렬
  • [필수] 콘텐츠 임시 저장 / 게시 / 비공개 상태 관리
  • [선택] 콘텐츠 변경 이력 추적 (감사 로그)

3.2 커뮤니티 기능

  • [필수] 게시판 생성·관리 (관리자가 게시판별 권한 그룹 지정)
  • [필수] 게시물 작성/수정/삭제 + 이미지 첨부
  • [필수] 댓글·대댓글 (1단계 깊이)
  • [필수] 좋아요 / 북마크

5. 기술 제약사항

  • 프론트엔드: Next.js 14 App Router 기반 — SSR/SSG/ISR 혼합으로 SEO + 성능 동시 확보
  • 백엔드: NestJS 모듈 기반 도메인 분리 — 향후 모듈 추가 시 영향 범위 최소화
  • 데이터베이스: PostgreSQL 15 — JSONB·GIN 인덱스로 유연한 메타·검색 대응
  • 인증: NextAuth.js (FE 세션) + JWT (BE 보호 라우트)
  • 리치 에디터: Lexical (Notion 수준 표·이미지·임베드 지원)
  • 인프라: AWS (EC2/ECS + RDS + S3 + CloudFront + Route53) — 또는 Vercel + Supabase 옵션 협의 가능
  • CI/CD: GitHub Actions (PR마다 lint/test/build, 메인 머지 시 자동 배포)

6. 범위 외 사항 (Out of Scope)

  • 광고 관리 시스템(ADMS) 본 개발 — 본 범위에서는 확장 가능 아키텍처 설계까지만 포함
  • 전문가/사용자 매칭 시스템 본 개발 — 동일하게 모듈 확장 지점 설계까지 포함
  • 모바일 네이티브 앱 (반응형 웹으로 대응)
  • 실시간 채팅·알림 푸시 서버 — 이메일 + 인앱 알림으로 시작
  • 결제·과금 — 본 범위에 결제 시스템 미포함
  • 콘텐츠 데이터 입력 작업 — CMS 제공, 데이터 입력은 클라이언트 담당
  • 다국어(i18n) — 한국어 단일 우선, 구조만 i18n-ready로 설계
